The catalogue update

Your new sheet is not an edit to the current catalogue. It is a different catalogue: about half the products change, a colour dimension appears that the site has never had, and sixteen products retire. This sets out exactly what changes, what it costs, and the four decisions I need before writing code.

All 35 rows resolve to real image folders, all 165 images in the zip are accounted for, and there are no orphans and no missing files. D1 — Decision

How should colourways work?

Option A — separate products

“Xyron Black” and “Xyron White” become two listings. No new code. But the same chair competes with itself in search, a shopper cannot switch colour without going back, and the category page shows near-duplicates.

~0 days

Option B — a colour picker recommended

One product page, swatches that swap the gallery and the price, and the basket adds the chosen colour. This is how Shopify models it natively, so the cart and checkout already understand it.

~1–2 days

Why I recommend B despite the cost

The basket is already built and gated behind ?cart=on. It adds a variant to the cart, because Shopify's Cart API is variant-bound. If we choose Option A, every colourway needs its own Shopify product, and the day you want a picker, the product IDs all change again and every link breaks a second time. B costs a day now and nothing later.

Deleting a page is not the same as retiring a product

If these URLs start returning 404, the site loses whatever ranking they had and anyone following an old link hits a dead end. The fix is a 301 redirect from each retired product to its nearest replacement — the leather and fabric chairs to the new Performance Mesh Chairs page, the storage and stand accessories to Accessories. The site already has redirect machinery for exactly this; I would add these to it.

Confirm: is the whole leather chair line (Nexor, Rider, Valerio) genuinely discontinued, along with monitor stands, CPU stands, storage boxes and desk hooks? That is an entire material line and four accessory ranges leaving at once, so I would rather ask than assume.

D4 — Decision

“Neuro” or “Neuro Mesh Chair”?

The sheet names products bare: Neuro, Xyron, Modura. The site currently uses Neuro Mesh Chair, which is also the URL (/chairs/neuro-mesh-chair/) and the search-result headline.

On the pageIn GoogleIn the basket
Bare nameFine — category is right above it Weak “Neuro” means nothing Vague
Full nameSlightly repetitive Strong Clear

My recommendation: show the bare name as the page heading, keep the full name for the browser tab, search results and basket, and do not change any existing URL. Renaming /chairs/neuro-mesh-chair/ to /chairs/neuro/ would throw away the ranking that page has built for no gain.

08 — Proposed plan

How I would build it

1. Catalogue rebuild behind a flag

New products.json with a variant dimension, images imported and optimised, redirects written for all 16 retirements. Built behind a preview flag exactly like the basket, so you can inspect the whole new catalogue on the live domain while ordinary visitors still see today's site.

2. Colour picker on the product page

Swatches that swap gallery and price. Falls back cleanly to a single-colour product where there is only one.

3. Shopify reconciliation

Archive the 16 retired products, create the 9 new ones, update prices and photography on the rest, and rebuild each product's variants. Then regenerate the variant IDs the basket depends on.

4. Copy pass

Your specifications in, my prose around them, your approval before it ships.

5. Flip the flag

One deploy. Old catalogue out, new catalogue in, redirects live the same second.

09 — Risks

Three things worth knowing

The basket's product IDs will all change

The basket currently knows 34 Shopify variant IDs. After this, there will be 35. Anything referencing an old ID stops working, so the catalogue change and the Shopify sync have to ship together, not a day apart.

Search rankings will move

Retiring 16 products and 6 category pages is a real change in the site's surface area. Redirects preserve most of it; nothing preserves all of it.

Nothing here touches the go-live blockers

Payments, policies and shipping are still the gate on taking real orders. This work is independent of those and can proceed in parallel.
